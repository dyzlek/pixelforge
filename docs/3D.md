# Architecture et Specifications du Moteur 3D Retro PixelForge

Ce document formalise les choix d'architecture, les specifications techniques et le modele de donnees pour l'extension 3D retro de PixelForge (v4.0).

---

## 1. Vision et Identite

L'objectif de PixelForge 3D est d'etendre la philosophie du moteur (un seul fichier JSON, Blueprints visuels, test F5 instantane, export HTML autonome sans compilation) a la troisieme dimension, dans une esthetique resolument retro (voxel, low-poly, textures pixel art, rendu basse definition affine sans filtrage bilineaire).

### Principes directeurs :
1. **Un seul fichier JSON** : Tout le contenu 3D (modeles voxel, scenes, materiaux, eclairages) est stocke dans le fichier `.pixelforge.json`.
2. **Runtime autonome sans import** : `src/runtime3d/engine3d.js` ne contient aucun import ES et s'inline directement dans l'export standalone.
3. **Meme logique de scripting** : Les scripts d'objets conservent la signature `(self, game, input, on)` et les concepts cles (collide, overlap, timer, inputs).
4. **Rendu retro basse resolution** : La scene est rendue dans un tampon hors-ecran (ex: 320x180 ou 480x270), puis mise a l'echelle avec un filtre au plus proche voisin (nearest).
5. **Zero dependance lourde au demarrage du studio** : Three.js est charge a la demande via import dynamique (`import('three')`) uniquement lors de l'ouverture d'un document 3D ou du lancement d'un jeu 3D.

## 2. Arbitrages Techniques

### 2.1 Moteur de rendu : Three.js (r16x)
- **Pourquoi** : Standard de l'industrie web, stabilite prouvee, integration facile avec un CDN (cdnjs / unpkg) pour les exports HTML autonomes, compatibilite WebGL2 et WebGPU.
- **En developpement / studio** : `import('three')` via npm.
- **En export HTML** : Injection d'un script CDN Three.js minifie ou inlining bundle.

### 2.2 Moteur physique : Physique AABB / Boite & Capsule avec Raycasting
- **Approche** : Pour conserver un moteur 3D ultra-leger, deterministe et sans runtime WASM volumineux, PixelForge implemente un moteur de physique retro sur mesure base sur :
  - Boites de collision englobantes orientees axes (AABB) et capsules pour les entites mobiles.
  - Voxel GridMap Collider : generation de boites fusionnees pour la grille de blocs.
  - Detection sol / parois avec correction de penetration elastique et friction.
  - Raycasting 3D pour la detection d'obstacles et les tirs.

### 2.3 Systeme de coordonnees
- **Convention Three.js standard** :
  - Axe X : horizontal (droite +X, gauche -X).
  - Axe Y : vertical (haut +Y, bas -Y, gravite dirigee vers le bas selon -Y).
  - Axe Z : profondeur (vers l'observateur +Z, vers l'horizon -Z).
  - Echelle d'unite : 1 unite 3D = 1 metre = 1 bloc de la GridMap.
  - Angles : angles d'Euler en radians pour le calcul interne, exposes en degres dans l'inspecteur et les Blueprints.

## 3. Modele de Donnees du Projet (JSON Schema)

Le projet s'enrichit de nouvelles collections optionnelles dans le fichier de sauvegarde `.pixelforge.json` :

### 3.1 Reglage de dimension (`settings.dimension`)
- Valeur : `'2d'` (defaut) ou `'3d'`.
- Permet au studio de configurer les panneaux, la barre d'outils et le runtime approprie.

### 3.2 Modeles 3D (`models[]`)
Deux types de modeles sont supportes :
1. **Modeles Voxel** (`type: 'voxel'`) :
   - Grille discrete jusqu'a 64x64x64.
   - Slices : tranches de texte ou matrices de couleurs indexees dans la palette (0-9a-f).
   - Frames : suite d'images cles pour les animations (ex: 'idle', 'walk', 'attack').
   - Maillage optimise par l'algorithme Greedy Meshing cote client.
2. **Modeles glTF / GLB Low-Poly** (`type: 'gltf'`) :
   - Fichier glTF/GLB embarque sous forme de data URL base64.
   - Avertissement visuel dans l'inspecteur si la taille depasse 2 Mo.

### 3.3 Materiaux (`materials[]`)
- Definition du rendu de surface :
  - `color` : couleur hexadeeimale issue de la palette.
  - `textureSpriteId` : texture pixel-art optionnelle appliquee avec filtre `NearestFilter`.
  - `roughness`, `metalness` : proprietes PBR simples ou rendu flat-shading non eclaire.
  - `doubleSided` : booleen pour le rendu double face des vegetations et panneaux.

### 3.4 Scenes 3D (`scenes3d[]`)
Chaque scene 3D remplace ou complete les cartes 2D (`maps[]`) :
- `id`, `name`, `folder`.
- `gridmap` : dictionnaire discret de coordonnees entieres `"x,y,z": blockTypeId` representant les blocs solides du niveau (sols, murs, piliers).
- `entities[]` : instances d'objets positionnees :
  - `id` : identifiant unique de l'instance.
  - `objectId` : reference vers un objet du projet (`objects[]`).
  - `x`, `y`, `z` : coordonnees reelles dans l'espace.
  - `rotationX`, `rotationY`, `rotationZ` : orientation en degres.
  - `scaleX`, `scaleY`, `scaleZ` : echelle de l'instance.
  - `props` : variables locales surchargees.

### 3.5 Environnement (`environment`)
- `skyColor` : couleur du ciel (hex).
- `horizonColor` : degrade d'horizon retro.
- `fog` : `{ enabled: true, color: '#1a1c2c', density: 0.04 }`.
- `ambientLight` : `{ color: '#ffffff', intensity: 0.6 }`.
- `directionalLight` : `{ color: '#ffeedd', intensity: 1.0, position: [10, 20, 15], shadows: true }`.

## 4. Pipeline de Rendu Retro

Le charme des jeux 3D de l'ere 32-bit (PlayStation 1, Nintendo 64, Saturn) repose sur des contraintes materielles specifiques :

1. **Rendu Hors-Ecran Basse Resolution** :
   - Un `WebGLRenderTarget` de taille reduite (par defaut 320x180 ou 480x270).
   - Affichage final sur un canvas plein ecran via un shader de post-traitement avec interpolation Nearest.
2. **Filtre de Textures Nearest** :
   - Toutes les textures chargees ont `minFilter = NearestFilter` et `magFilter = NearestFilter` sans mipmapping flou.
3. **Vertex Snapping (Option PS1)** :
   - Shader de sommets custom qui quantifie les coordonnees projetees a l'ecran pour reproduire le leger sautillement jittery caracteristique des consoles sans tampon de profondeur sub-pixel :
   ```glsl
   vec4 snapPos = gl_Position;
   snapPos.xyz = snapPos.xyz / snapPos.w;
   snapPos.xy = floor(snapPos.xy * resolution * 0.5) / (resolution * 0.5);
   snapPos.xyz *= snapPos.w;
   gl_Position = snapPos;
   ```
4. **Dithering de Couleur Ordre (Ordered Bayer Matrix)** :
   - Trame ordonnee 4x4 ou 8x8 reduisant le gradient de couleur a la palette Sweetie 16 ou 256 couleurs retro.

## 5. Export HTML Standalone 3D

Comme pour la 2D, l'export standalone produit un fichier HTML unique :
- Inclusion de Three.js via script CDN.
- Inclusion de `src/audio/chip.js` pour la musique et les sons chiptune.
- Inclusion de `src/runtime3d/engine3d.js` inline.
- Injection du projet JSON dans une balise `<script type="application/json" id="pixelforge-project">`.
- Lancement instantane hors connexion.
